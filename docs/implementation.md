# 五个社区应用的原生插件试迁移

2026-09-20。本轮从调研进入实现，五个应用均有独立 Rails 后端、插件数据表、Glimmer 页面、论坛用户组授权和铃铛通知。它们不依赖旧 Next.js 服务，也不要求启用 RSC。状态是**可在隔离论坛验收的首版**，不是已切换的生产系统。

## 已实现的业务

| 插件 / 入口 | 已实现 |
| --- | --- |
| `discourse-alumni-map` / `/alumni-map` | 名片编辑、自愿公开、论坛名可选展示、城市级坐标、搜索和列表、高德地图组件、管理隐藏/恢复 |
| `discourse-course-review` / `/courses` | 跨学期课程聚合、教学班、任课教师、导师库、双套多维评价、匿名评论、赞踩、举报、收藏、管理 |
| `discourse-rsdate` / `/rsdate` | 资料、学校组校区规则、模块问卷与版本失效、匹配池、Ruby Blossom、后台预览/发布/手工配对、当前和历史结果、定时发布、可选向量接口 |
| `discourse-whisper` / `/whisper` | 匿名树洞和回复、帖内稳定别名、图片、赞踩、举报、管理隐藏/恢复、独立禁言、实名查看理由与审计 |
| `discourse-seek` / `/food` | 店铺筛选和每日推荐、菜品、图库、评分与回复、收藏、分享卡、新店/资料修改申请、审核冲突检测、贡献记录、关于页 |

前端保留各自的应用页面，不转换为普通论坛帖子。当前采用统一的卡片、筛选、表单与手机布局，尚未复刻旧应用全部视觉细节。

## 共用机制

- 每个插件默认关闭，分别配置 `*_allowed_groups` 和 `*_admin_groups`。真正的论坛管理员可管理；插件管理组不会因此获得论坛管理员权限。游客只可浏览觅电公开内容。
- 写入使用当前论坛用户；请求编号和事务锁支持重试，不能由客户端指定操作者。内容、图片和后台操作分别校验权限。
- 原生 `Notification` 铃铛通过事务事件表投递、去重，后台每分钟补发。匿名业务不写真实发起人，RSDate 不在通知正文透露结果资料。历史导入不重发通知。
- 五个插件与 RSC 使用兼容的自定义通知渲染器。Discourse 的 `custom` 渲染器注册会覆盖前一个，所以同时更新了 RSC 的渲染器；其他第三方插件若也替换它，需要额外兼容测试。
- 图片经 vips 校验、缩放、重新编码和去元数据；原图不保留。当前图片存入各插件 PostgreSQL 表，由鉴权路由返回，树洞图片不使用公开 Discourse 上传地址。单张输入上限 10 MB、输出 1 MB、1200 像素、每用户 50 MB。这会增加论坛数据库备份体积，大媒体规模上线前应评估私有对象存储实现。
- 后台任务使用论坛 Sidekiq；启用开关同时控制任务。所有功能依然共享论坛进程和数据库，独立插件不等于独立故障域。

## 导出与导入

每个插件 `script/export_legacy.mjs` 从旧项目生成的 Prisma client 导出明确列出的业务表，数据库只读事务、RepeatableRead 快照，必须显式提供 `LEGACY_DATABASE_URL`。不会自动读取旧应用 `.env`。运行导出时需要旧项目 Node 依赖；插件日常运行不需要 Node 后端。

```sh
LEGACY_DATABASE_URL='postgresql://...' node script/export_legacy.mjs /path/to/old-app /private/export.json /path/to/old-media
```

觅电旧项目路径应指向 `seek-uestc/eating-app`。没有图片的项目可省略媒体目录。输出文件权限 0600，图片侧目录 0700，按 SHA256 保存；已有导出不覆盖。失败可能留下保留文件或不完整侧目录，应使用新路径重新导出。请将导出视作包含私密资料的备份。

将导出文件及同名 `.media` 侧目录放入隔离 Discourse 容器，可执行：

```sh
RAILS_ENV=production bundle exec rails runner plugins/discourse-whisper/script/import_legacy.rb /private/export.json
```

默认导入演练：实际走事务和校验，结束回滚，输出计数及文件哈希。正式导入需插件关闭且自身业务表为空，设置 `RIVER_IMPORT_APPLY=1` 与 `RIVER_IMPORT_SHA256=<已核对的哈希>`。相同文件重复正式导入返回已完成，不重复写入。不同文件不能覆盖现有业务。以上示例插件目录替换为对应项目。

所有源记录保存在仅后端使用的 Legacy 表，运行所需模型另外转换并保存旧 ID 映射。论坛用户 ID 必须存在；操作者仍须核实旧 DiscourseConnect 来源确为同一论坛，不能把“编号存在”当作完整身份核验。旧角色不会导入为论坛权限。

- **觅电旧账号：** `discourse:<ID>` 可映射；GitHub/dev 账号默认阻止导入。经核实后在导出 JSON 添加 `user_mapping`（旧本地 ID → 论坛 ID），重新核对文件哈希。也可显式使用 `RIVER_ALLOW_UNMAPPED=1` 保留未映射历史来源，运营必须接受这些内容暂不归属真实账号。
- **觅电收藏：** 原来存在浏览器 localStorage，数据库导出不包含。`script/export_favorites.html` 需从旧站同源提供给用户下载，用户再在新插件导入旧店铺 ID；本轮没有修改旧站。
- **觅电待审修改：** 旧系统没有可验证的版本号，保留申请与快照，迁移后的旧待审编辑需重新提交，避免覆盖新数据。
- **RSDate：** 当前模块问卷、答案、当前/历史配对和周期会转换；更早的旧版问卷仅归档，不伪装成现行模块。定时周期键沿用旧 `YYYYMMDDHHmm`，发布时区/星期/时分需与旧部署一致（首版时区支持上海和 UTC）。
- **树洞：** 保留旧 publicCode、回复关系、稳定别名、禁言、实名审计。历史通知归档，不重新推送。
- **图片：** 必须提供完整媒体清单；校验哈希后转换。旧图片 URL 不会自动在旧域名重定向。

生产切换仍需实际数据的隔离导入对账、用户映射核验、媒体盘点、配置/负载验收。先停旧写入与旧 RSDate cron，再最终导入和开放新入口；发生新写入后不能直接重开旧库写入作为回滚。

## 本轮边界

1. 尚未接入 Discourse 统一 Reviewable 队列；举报和审核在各插件原生管理页。
2. 未实现论坛用户合并、删除/匿名化、完整隐私导出和自定义全文搜索的生命周期钩子，上线前需要明确并实现账号处理规则。
3. 高德组件和地理编码已写入；真实密钥、域名白名单、在线地图 CSP/手机操作尚未联调。无密钥时列表仍可使用；国家城市采用文本输入，没有旧版完整地名选择器和缩放层级聚合抽屉。
4. 课程 Excel/导师抓取尚未做成论坛后台上传工具，可先从旧工具入库后统一导出迁移。旧链接跨域重定向未配置。
5. RSDate 向量接口可选且默认关闭，未调用真实计费接口；缺失向量时仍能按其他维度配对。同分图可能选出与旧实现不同、但配对数和总分相同的最优方案。真实规模性能与完整业务评分回归仍需上线数据样本。
6. 通知当前为铃铛；没有实现邮件、浏览器推送或默认自动私聊。
7. 只迁移了可直接承接的旧数据语义，旧域名、外部地图、收藏跨域入口、生产负载和全部旧页面体验不在本轮自动验收的覆盖范围。

## 文件位置

五个插件分别在 `/opt/discourse-{alumni-map,course-review,rsdate,whisper,seek}`，集成测试、浏览器流程、截图和验证记录在 `/opt/discourse-community-test`。调研文档仍保留当时的结论；本文件说明之后的实际实现进度。
